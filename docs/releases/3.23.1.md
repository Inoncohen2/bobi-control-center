# 3.23.1 — report write safety without hiding the live bridge

Date: 2026-08-31

The connection adapter and Home Assistant's management contract answer two
different questions. The UI used to label both as “write mode”, so an adapter
that correctly blocked direct writes could make a working verified bridge look
disabled.

This release separates them:

- `/health` and `/api/bobi/connection` report `unrestricted_writes: false`;
- the settings screen labels that invariant **כתיבה ישירה — חסומה (כנדרש)**;
- the same screen reads `writes_enabled` from the live management contract and
  reports **כתיבה דרך גשר בובי** independently;
- the dashboard no longer describes the whole application as read-only.

The safety boundary is unchanged. No endpoint can enable Home Assistant's
master switch, and no write can skip preview, confirmation, the bridge
allow-list or read-after-write verification.

The deployment paired with this release also moves the Bobi Edge Function's
token verifier out of source code into a one-row, service-role-only Supabase
configuration table with forced RLS and an explicit deny-client policy. Edge
version 6 loaded that verifier successfully in a live Home Assistant ping. One
unreferenced voucher test object was moved, recoverably, to
`_trash/_orphans/`; no active orphan remains.
