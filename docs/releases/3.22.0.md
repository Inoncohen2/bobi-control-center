# 3.22.0 — close the remaining integration and security gaps

Date: 2026-08-31

This release is the Control Center half of the Bobi gap-closure pass.

## Supabase / voucher storage

`bobi-storage` is now v5. The production Edge Function remains custom-token
authenticated and the Home Assistant side still never receives a Supabase
privileged key.

The storage path now provides:

- strict write allowlists for profile, voucher, task, context, schedule,
  notification and action-log payloads;
- request/body size bounds and pre-decode media-size checks;
- JPEG/PNG/WEBP signature verification in addition to declared MIME type;
- cleanup of a newly uploaded object if its metadata insert fails;
- rollback of Storage moves if soft-delete/restore metadata updates fail;
- short-lived signed URLs for active voucher media (`voucher.media.signed_url`);
- `voucher.get`, which omits the redeemable code unless the caller explicitly
  asks for it;
- support for an active and previous token hash so credentials can be rotated
  without a flag day.

The bucket remains private and the direct anon/authenticated RLS deny policy is
unchanged.

## Control Center

- Version raised to 3.22.0 in all three release locations.
- README and repository rules now describe the current bridge-driven
  architecture rather than the old Phase-3A/write-switch state.
- The repository now states the voucher privacy rule explicitly: normal wallet
  snapshots carry neither redeemable codes nor permanent/public image URLs.
- Live-contract fixtures are documented as dated evidence rather than permanent
  truth; static service counts are no longer architectural claims.

## Home Assistant side still required before the two new household screens are live

These are bridge changes and must be applied through authorized Home Assistant
tooling, then verified against the real installation:

1. `bobi_cc_lists_snapshot` — publish only the curated household lists, never
   Bobi's internal todo stores.
2. `bobi_cc_vouchers_snapshot` — read the Supabase wallet, omit `code`, and
   publish only safe voucher detail. Media access must use the short-lived
   signed-URL operation.
3. The voucher ingestion path must call `voucher.media.upload` after
   `voucher.upsert` when a photographed voucher is accepted.
4. `rule_edit` remains unavailable until the Home Assistant rule bridge gains a
   verified edit path; it must not be advertised before then.

The Control Center deliberately does not bypass these missing bridges by talking
directly to Supabase or Home Assistant entities.
